# appforge reference architecture

Read `references/where-code-goes.md` before writing code in a generated app, and `references/events.md`
when touching events, reactions or subscribers. The generated app also documents itself in
`docs/architecture.md` and `docs/domain.md`.

## Shape
- **Postgres (Supabase) is the brain.** Data, authorization (RLS on every table), workflow engine,
  transactional outbox, internal reactions and scheduled jobs (pg_cron) are SQL. The web app never decides
  permissions: it calls the database as the signed-in user.
- **Next.js** (`src/`) renders generic pages driven by the generated metamodel (`src/lib/model.ts`):
  `/e/[entity]` list, `/e/[entity]/new`, `/e/[entity]/[id]` (facts, workflow actions, edit form, history),
  a dashboard with the user's inbox, admin pages for users/roles and integrations.
- **Dispatcher** (`worker/dispatcher.ts`) delivers outbox events to webhook subscribers (CloudEvents 1.0,
  Standard Webhooks signatures, at-least-once, exponential retry, dead letters).
- **Subscribers** (typically n8n) perform external effects: emails (using `data.recipients` and
  `template_key`), API calls, document generation.
- Optional **edge processes** (e.g. a Raspberry Pi driving hardware, as in ACS) are subscribers and clients of
  the same API; they never bypass the database rules.

## Generated layers (do not edit)
| Layer | Files | Evolution |
|---|---|---|
| core | `supabase/migrations/*_appforge_core.sql` | generated once |
| structure | `*_appforge_structure.sql`, structural part of `*_appforge_evolve_N.sql` | additive deltas generated; destructive ones → `*_manual_evolve_N*.sql` written by hand |
| behaviour | `*_appforge_behavior.sql`, behaviour part of evolve migrations | regenerated in full each time |
| artefacts | `src/lib/model.ts`, `src/lib/events/catalog.ts`, `docs/domain.md`, namespace `model` of `messages/*.json` | rewritten each time |

`.appforge/lock.json` records the hashes; a PreToolUse hook blocks edits of these files. Change `app.yaml`
and run `/appforge:generate` instead.

## Database contracts available to hand-written code
- `public.perform_transition(entity, id, transition, comment)` / `available_transitions(entity, id)`
- `public.emit_entity_event(entity, id, type, extra jsonb)` — publishes a declared event with payload + recipients
- `public.<entity>_principals(row)`, `public.<entity>_can(action, row)`, `public.can(entity, action, id)`
- `public.<entity>_json(id)` — event payload of a row; `public.entity_payload(entity, id)`
- `public.my_inbox()`, `public.record_history_of(entity, id)`
- `public.custom_<handler>(p_event public.events)` — body of `custom` reactions
- Session flags: `app.in_transition` (state changes), `app.system` (readonly fields) — set them only inside
  security-definer functions, with `set_config(..., true)` (transaction-local).
